# Verify Cloud execution and one scheduled continuation

This is an optional maintainer procedure, not an instruction executed by installation. Obtain explicit authorization for the one-off callback before running step 4. Do not merge, release, deploy, create unrelated chats, or install the plugin into a personal account as part of this proof. Never use Firecrawl.

1. Read AGENTS.md, adapter/rules.md, and cloud/networking.md. Record repository, branch, HEAD, runtime versions, and the host's exposed execution identity in ignored `work/cloud-proof.json`. Keep personal identity and schedule data out of commits and public reports.
2. Confirm the intended reviewed revision. Fetch only through the host's supported network mode; do not reset dirty or divergent work. Run full package validation, the Python tests, and scripts/probe_upstream.py. Record actual exit codes and accepted/candidate tree SHAs without changing the accepted lock.
3. Inspect the actual host's native scheduling capability and documented execution destination. Do not substitute a reminder, local desktop heartbeat, separate coding chat, undocumented endpoint, or external runner. If the capability is absent, report that precise boundary.
4. If authorized and supported, create exactly one short-delay callback in this Cloud conversation. The callback must run pwd, git rev-parse HEAD, and scripts/probe_upstream.py, append the actual result to the ignored receipt, and end. It must not create another callback or recurring schedule.
5. Read back the callback receipt and verify that commands actually executed against the expected repository and revision. Check the actual execution time separately. A successful initial run or a completed reminder alone is insufficient.

Return a sanitized command/outcome summary and the private receipt location. Keep changed-source adaptation and recurring-schedule activation as separate acceptance steps.
