### Worktree and simulator cleanup

1. Snapshot and audit. Record available disk space with the platform filesystem API. Fetch the intended base explicitly, then run `python "<skill-dir>/scripts/worktree-audit.py" [-b <pr-base-ref>] [repo-path]`. The script reads NUL-delimited Git worktree paths, including spaces, and reports sizes, last commits, cached merge evidence, tracked and untracked changes, and PR state. Without `-b`, it resolves the remote default branch, then origin/main or origin/master. Audit failures are unresolved evidence, never proof of safety.
2. Establish usage. Obtain current pinned and active chat/worktree information from supported scoped tools or the user. When available supply `--activity-index <file.json>`, an explicit map of absolute paths to `{ "active": false, "pinned": false, "source": "verified evidence" }`. Do not scan unrelated transcripts. Account for sibling worktrees created by active chats. Missing evidence stays `verify-usage`; a pinned or active chat wins over merge status.
3. Resolve every hold. `hold-uncommitted` includes untracked files; do not assume they are disposable. `hold-open-pr`, `hold-locked`, `review-unpushed`, `review-unmerged`, `review-incomplete`, and `verify-pr-state` require their specific evidence before reconsideration. A closed PR is not proof of a merge. A squash-merge claim must refer to the exact worktree HEAD. Use actual delegation controls only when authorized and available; otherwise inspect these questions sequentially.
4. Present a concrete delete/retain inventory. `candidate-for-review` is advice, not permission. Name each absolute path, branch, local changes, ignored assets, usage evidence, and recoverability. Honor the user's existing authorization; otherwise obtain approval for that concrete set. Preserve work that is uncommitted, unpushed, in use, or of unknown value.
5. Remove only approved paths. Prefer the host's managed-worktree archive tool when it applies; it preserves a recoverable snapshot. For ordinary Git worktrees use `git worktree remove <absolute-path>` without force. If Git refuses because files remain, inspect those files and resolve their retention first. Before any recursive removal, verify the resolved target stays inside the explicitly approved root, use one native shell end to end, and preserve needed ignored assets. Prune stale Git metadata only after checking the affected entries. Re-list worktrees and measure disk space again.
6. Consider other reclaimers only within scope. On macOS, Xcode simulators, DerivedData, device support files, and package caches can be inspected with their platform tools. On Windows, use the applicable application's cache controls and filesystem APIs. Neither application chat databases nor workspace snapshots are disposable caches by default. Name the exact candidate data and recovery limits before deletion; do not infer authorization from a worktree cleanup request.

This playbook changes user state without a code review, so the inventory, usage evidence, and recovery checks are required.

**Reply:** Report before/after free space, the approved worktrees actually archived or removed, and a concrete reason for each retained path.
